# 使用指南

## 运行与聊天

“运行”页负责开始、暂停和切换聊天。程序默认暂停，不补回复启动前或暂停期间的旧消息。关闭窗口会停止当前控制台；修改代码后需重启。

“聊天”页的允许列表决定可以读取、回复和转告的目标。程序首次运行含通用占位示例，应将其替换为自己的测试聊天。选中聊天后再点击“开始 / 继续”。

多聊天模式会检查微信会话列表，在当前聊天没有待回复消息且满足停留时间后切换。指定联系人的私聊优先；模型判断的转告只能发到允许列表里的其他聊天。群聊上下文可以提供给指定私聊，私聊内容不会主动加入群聊上下文。模型仍可能误解转告意图，请先在测试聊天验证。

## 让她给任意聊天发一句话

只在指定联系人的私聊里有效，不经过模型：“给某某发：明天见”“去给某某私聊发：晚安”“跟某群说：今晚八点”“在测试群里艾特小王说：周末一起吃饭吗？”。冒号后面的话照发（最多 500 字；换行、连续空格会合并成一个空格）；“艾特小王”会像手动一样在群成员列表里选中小王，对方会收到提醒；说“艾特我”就是艾特你自己。成员列表里找不到这个人时，改写成普通文字“@小王 ”，回报里会说明。

不按上面的格式说也可以，例如“在群里艾特我，说：测试一下”“去测试群跟小王打个招呼”：本地模型只负责读出“发到哪、艾特谁、说什么”，程序再核对——聊天必须是你点名的（全名或简称），或者只有一个群时的那个群；艾特的人必须是你写出来的名字、你自己，或群里出现过的成员（外号借助群记忆对应）。对不上就回私聊问你，不会猜着发。

收件人可以是任意微信聊天，不必在允许列表里。聊天名不能含空格、冒号或逗号，也不能是 claude、codex、deepseek、本机。群名可以用简称：只有一个允许列表里的聊天名包含它时才用那个聊天，对上好几个就不发。其他名字按原样处理：当前已打开或会话列表里有这个名字就直接用，否则用微信搜索，搜索结果不唯一或找不到就不发。如果微信里有同名的聊天，请先确认会话列表里那个就是要发的。发完回到私聊回报“已发给「某某」：…”，没发出去会说明原因；点了发送但结果不确定时只提醒你查看微信，不会重发。暂停期间发的这类指令只记录、不执行。

## 拉黑与记忆命令

在指定联系人的私聊里，或者在群里艾特她，都可以说：

- `拉黑 某某`、`不允许再接收@某某 的消息`：之后在所有聊天里都不再接收这个人的消息。名字要和群里显示的一致。
- `解除拉黑 某某`、`黑名单`。
- `总结记忆`、`整理一下记忆`：立刻整理记忆并回报结果。在群里说只整理这个群，在私聊里说会整理所有打开过的聊天，每个聊天约一分钟。

群里只认主人本人艾特她时说的这几条命令；群昵称来自截图识别，所以代发和派任务仍然只在私聊有效。“别听他们瞎说”这类普通的话不会被当成拉黑：名字不认识时，要明确写“拉黑”或带 @。

## 派任务给本机 agent

只在指定联系人的私聊里有效，群聊里同样的话按普通聊天处理。这个功能默认开启、默认不需要口令；不需要时请在“聊天”页关闭“允许派任务”，或者设置口令。

- `给claude 口令 任务`（也可以写给codex、给deepseek、给本机）：派出任务，回复“收到，交给 X 了，做完告诉你”。同一个 agent 同时只做一个任务。
- `任务`：列出进行中的任务和最近 3 个已结束的任务。
- `停掉 codex`：停掉这个 agent 正在跑的任务。

任务做完后，本地模型会把输出压成一句话发回这个私聊；完整输出保存在 `data/agent_logs/`。指令被识别后，口令会在进入聊天上下文和日志之前去掉；口令写错或格式不对时，这句话按普通聊天原样记录。暂停期间，以及用 `--reply-latest` 启动时最后一条旧消息里的指令，只记录不执行。agent 会在本机执行命令和改文件，请只交给它可以放心的任务，并先在测试聊天里验证。

## 人格与节奏

在人设页编辑名字、性格、说话方式和感兴趣的话题，保存后下一轮生效。名字和机器人昵称也用于识别群聊点名。切换人格后，可清空旧上下文以减少旧风格影响。

节奏页可设置等候时间、消息间隔、回复长度、主动接话与图片、搜索、记忆等功能。私聊的主动接话默认间隔为 150～240 秒，无人回应后不连续追问。群聊的插话由新消息触发，并受概率、点名和频率控制。

## 模型与资源

模型页列出 LM Studio 本地模型，支持显存估算与加载。默认使用全部 GPU 卸载，加载器只切换机器人自己的模型实例；进程内存回收辅助函数则可能作用于其他 `llama-server` 进程。

视觉模型连续分析图片时仍可能使显卡忙碌。当前代码会在模型加载后和表情整理后尝试收缩推理进程工作集；这只是内存管理辅助措施，不能保证降低所有场景的资源消耗。

## 群聊校准

微信 4.1.x 的昵称、头像和消息行结构可能随版本改变。打开测试群，点击只读校准入口，检查 `data/debug/` 中报告与截图，按需要调整成员名单和布局。

截图和报告含群聊内容，勿上传到仓库或公开问题区。OCR 不能识别时可人工填写成员名单。无法可靠区分新旧消息时，程序会放弃本批回复。

## 表情

她优先发表情包图片：连续两条回复没发表情包时会提醒模型挑一张（`sticker_every`，默认 2）。微信小表情一条最多一个，最近 4 条回复里用过的不会再用；模型把表情包编号写进文字时会被去掉。

本地表情库支持 PNG、JPEG、GIF、WebP。先整理图片描述，再检查是否准确；描述应说明适用语境。手动改过的描述不会在重复整理时覆盖。

自动收集的表情先进入待审核列表。聊天截图无法保留 GIF 动画。发送图片会暂时改写剪贴板，程序只尝试恢复原文字，原图片剪贴板内容不能完整保留。

## 记忆编辑

进入“记忆 → 编辑记忆”，选择人物或说法进行修改，也可新增、删除，或更改聊天风格。保存后下一次回复使用新内容。

- 人物最多 200 个，每人最多 12 条事实，每条 40 字。
- 印象最多 60 字，聊天风格最多 80 字。
- 常用说法最多 60 个，词条最多 12 字，含义最多 40 字。
- 不合法的内容会提示错误，不会静默截断。
- 保存前备份，若其他整理任务已经更新记忆，则提示冲突并保留草稿。

## 故障检查

先暂停，检查微信窗口是否可见、聊天标题是否匹配、模型 API 是否在线，再查看本地状态提示。群昵称错误优先校准界面与成员名单；模型失败优先检查模型名称和上下文长度。发送结果不确定时，请直接查看微信，避免重复发送。
