# 小千 · 本地大模型 AI 微信群友 / 微信聊天机器人

[English](README.md) | 简体中文

小千是一个在 Windows 上运行的 AI 微信群友 / 微信聊天机器人，用 LM Studio 里的本地大模型（如 Qwen）驱动。她通过桌面微信 4.x 的界面自动化收发消息——不 Hook、不注入、不走网页协议——会读空气判断该不该接话，也会主动冒泡、记住每个人、发表情包、在群里真正艾特人、画图，还能把任务交给 Claude Code 或 Codex。

支持私聊、群聊和长期记忆。默认打开控制台后保持暂停，由使用者选择聊天并开始。项目仍处于试验阶段，微信版本、窗口布局和显示缩放都可能影响识别。

> **你在看 `server` 分支：小千服务器版。** 它让小千在一台独立的 Windows 云服务器上 24 小时在线，大脑换成 DeepSeek API。
> 本机版（LM Studio 本地模型、画图、派活给 agent）在 [`main` 分支](https://github.com/AnthonyZZH/xiaoqian-wechat/tree/main)。
> 整套服务器部署流程（买服务器、加固、装微信/QQ、守护、排错）见 [xiaoqian-server-deploy](https://github.com/AnthonyZZH/xiaoqian-server-deploy)。

## 服务器版（server 分支）

### 和本机版的区别

| | 本机版（main） | 服务器版（server） |
|---|---|---|
| 大脑 | LM Studio 本地模型 | DeepSeek API（`deepseek-flash`，默认关闭思考模式，JSON 输出，无工具调用） |
| 运行环境 | 自己的电脑，人看着 | 独立 Windows 云服务器，无人值守 |
| 画图 / Forge / 派活给 Codex·Claude·lms | 有 | 去掉（服务器无显卡，且与个人电脑隔离） |
| 上下文成本 | 取决于本地模型 | 每个聊天只带最近 20 条 + 滚动摘要 + 最多 5 条检索记忆，**不会越聊越贵** |
| 数据目录 | `data/` | 可放到程序外：`XQ_WECHAT_DATA_DIR`（如 `C:\xiaoqian\data\wechat`） |

### 服务器版新增 / 改动

- **主人转告（口语即可）**：在主人私聊说"去面包群说本小姐回来啦"，由模型理解是哪个允许的聊天，认不出再按名字重合兜底；她会用自己的口吻直接对那个群说话（不会说"主人让我来的"），发完在私聊回执。
- **转告到人并 @ 他**："给张哥发消息说对不起"——从记忆里的人物事实、群黑话（谁被叫什么）和群成员名单认出是谁；他有允许的私聊就私聊，否则去他所在的群里真正 @ 他；记录里没有就用微信自己的 @ 成员列表搜；有多个人选会回来问。不会 @所有人，不会 @主人。群里有人自称主人无效。
- **识图与表情**：收到的图片缩小后交给 DeepSeek 识别；表情包每轮从整个库里随机抽 20 个给她挑；别人发的新表情进待审核收件箱。
- **主人私聊能看到各群近况**（只给主人私聊，朋友私聊和群里看不到别的聊天）。
- **无人值守**：每次读消息前把微信恢复并置顶、把挡住它的其他程序窗口最小化（`XQ_WECHAT_KEEP_FRONT=0` 可关）；`--start` 启动即开始。
- **稳定性修复**：历史从前面截断后滚动摘要自动重新对齐；长历史下也稳定输出 JSON；控制台显示真实错误原因（日志文件只记代码）。
- **安全底线**：只连 DeepSeek 官方地址、拒绝代理与重定向；密钥只从环境变量读；转告有频率上限（每小时 10、每天 40）；主动发言有冷却和夜间静默。

### 配置与启动

1. 装好微信 4.x 并登录小号；Python 3.12（64 位）；`pip install -r requirements.txt`。
2. 设置环境变量：`XQ_DEEPSEEK_API_KEY`（DeepSeek 密钥）、`XQ_WECHAT_DATA_DIR`（数据目录，可选）。
3. `settings.json` 关键项：`chats`（允许的聊天及 private/group）、`owner`（主人私聊的标题）、`api_key_env`、`model.identifier`（如 `deepseek-flash`）、`thinking`（默认 false）。
4. 启动：`python app.py`（面板，暂停状态）或 `python app.py --start`（启动即开始）。服务器上建议配合部署仓库里的 `run_panel.py`（记录崩溃）和看门狗计划任务。
5. 上线前先跑一次"不发送测试"：读一轮、调模型、拦截发送，确认无误再开始。

## 功能

- **参与对话**：合并短时间内的连续消息，判断是否在对机器人说话；群聊中按点名、上下文和频率决定是否插话。
- **语音消息**：新来的语音会自动用微信自带的“语音转文字”转成文字再回复，私聊、群聊都支持，语音不会上传到别处。
- **私聊必接话**：私聊里对方发了消息就一定回；模型想沉默或回复被过滤掉时会再问一次，最后还有一句兜底。控制台“重新接话”按钮会针对对方最近说的话再回一句。
- **有脾气的人设**：拒绝下流、变态的要求，被骂会针对对方的话回击，但不人身攻击外貌、出身、性别、地域，不用歧视词。
- **主动接话与开话题**：私聊在一段时间后可延续话题；群里安静一阵后会自己冒个泡，也会隔几个小时主动找主人聊一句。到点时由模型判断有没有值得说的，没有就不说；有免打扰时段，连续没人接就暂停。
- **可编辑人格**：内置“小千”和“阿温”，支持新增、修改人格。
- **长期记忆**：按聊天整理人物档案、黑话和聊天风格；整理进度在重启后恢复，程序空闲时也会定时更新没有打开的聊天。可以手动编辑，保存前备份，遇到并发更新时提示冲突。
- **图片与表情**：视觉模型可描述图片，按描述选择表情；收到的表情可先进入待审核列表。
- **联网搜索**：使用 DuckDuckGo HTML 搜索，失败时回退 Bing。
- **多聊天调度**：只照看已加入允许列表的聊天，支持从指定联系人的私聊转告到允许列表里的其他聊天。
- **主人代发**：指定联系人的私聊里说“给某某发：…”或“在某群里说：…”，冒号后的话按名字发到任意微信聊天（群简称只在唯一对上时使用），不经过模型，发完如实回报。艾特会像手动一样从群成员列表里选人；不按格式的说法由本地模型读出后再核对。
- **画图**：说“画一只橘猫”“帮我画：…”“生成一张…”，由本机 Stable Diffusion WebUI Forge 画好发回原聊天。中文描述先转成 Danbooru 风格的英文标签；点名的角色（如“雪之下雪乃穿比基尼”）会先去 Danbooru 查她的标签、作品和常见外貌，正负提示词保证认得出是她，衣服和场景按要求来。原来用 Codex 联网找参考图再画的方式仍可手动选择。每个已允许的群聊或私聊可分别设置画图人选与每日张数，主人不限。控制台“画图”页会实时显示任务状态，并管理画过的图片。
- **说了就去做**：主人在私聊里随口提的实事（画图、查资料整理、做文件）会交给对应的 agent，她只回真实的回执，不再嘴上答应却不动手。
- **拉黑与记忆命令**：“拉黑 X”“解除拉黑 X”“黑名单”“总结记忆”，在私聊里说或在群里艾特她说都可以。
- **本机 agent 任务（默认开启，可关闭）**：指定联系人的私聊可以把任务交给本机命令行 agent（Claude Code、Codex 或 DeepSeek Harness），可设口令，做完后收到一句话汇报。见 [docs/USAGE.md](docs/USAGE.md)。

## 运行要求

- Windows 10 / 11，64 位 Python 3.11，安装时包含 Tkinter。
- 已登录的桌面微信。适配器面向 **微信 4.1.x**，曾在 **4.1.15.13** 环境试用，其他版本需要自行校准。
- LM Studio、本地模型和 `lms` 命令行工具。文字模型可聊天；图片识别和表情整理需要视觉模型。
- 群昵称用 RapidOCR 识别（随 `requirements.txt` 安装），Windows 自带的中文 OCR 作后备。
- 画图需要带 `--api` 启动的 Stable Diffusion WebUI Forge（默认 `http://127.0.0.1:7860`）和二次元 SDXL 模型，默认参数适合 waiIllustriousSDXL 这类 Illustrious 模型；可在 `data/settings.json` 里设置 `forge_root`、`forge_model`、`draw_params`。
- 足够容纳所选模型的显存；当前加载器请求全部 GPU 卸载。加载成功不代表所有配置下都能完全避免内存压力。

## 安装与启动

在项目目录中运行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

也可在安装依赖后双击 `启动小千.cmd`。首次运行会在本机创建 `data/`，仓库不附带任何聊天、记忆、表情、账号配置或模型文件。

1. 打开 LM Studio 的本地 API 服务，默认地址为 `http://127.0.0.1:1234/v1`。
2. 在控制台“模型”页选择已下载的模型。默认模型名称只是示例，请替换为自己安装的模型；`lms` 默认路径按当前 Windows 用户目录生成，需要时可修改 `data/settings.json`。
3. 在“聊天”页刷新会话，加入并选择需要照看的聊天，删除不使用的示例项。
4. 设置机器人微信昵称、指定联系人和人格。群聊先进行只读识别校准，再检查昵称是否正确。
5. 保持微信窗口可见，在“运行”页点击“开始 / 继续”。先用测试私聊验证收发，再启用群聊。

窗口被遮挡、最小化或发送结果不确定时，程序会停止本次收发并提示状态；请查看微信后再继续。

## 修改记忆与表情

- **记忆 → 编辑记忆**：新增、修改或删除人物档案、常用说法，或修改聊天风格；点击“保存修改”后下一次回复生效。
- 手动保存前的版本位于 `data/memory/backups/`。编辑期间记忆有新更新时，草稿会保留并提示冲突。
- 记忆会继续随聊天更新，手动修改不等于永久锁定；删除旧事实也不能保证模型今后不会从新聊天重新学到。
- 把个人表情图片放进 `data/stickers/` 后，在“表情包”页整理和编辑描述。分析大量图片会增加 GPU 负载。
- 从聊天界面收集的是截图，动图会变成静态图；本项目不包含微信收藏表情数据库的解密导出工具。

更多说明见 [使用指南](docs/USAGE.md)、[数据与隐私](docs/PRIVACY.md) 和 [第三方依赖与参考](THIRD_PARTY.md)。

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest test_core test_runner test_memory_edit test_websearch test_routing test_agents test_agent_bridge test_proactive -v
```

默认测试使用临时数据、模拟微信和模拟模型，不向微信发消息。真实搜索测试仅在 `LIVE_SEARCH=1` 时启用；OCR 测试依赖系统语言组件。测试不会替代当前微信版本的人工收发验证。

## 已知限制

这是桌面界面自动化工具，依赖窗口可见及界面结构稳定。群昵称 OCR、消息方向、引用和媒体识别均可能出错。连续快速切换聊天或大量新消息时，程序会优先放弃不确定的回复。搜索页面结构和访问限制可能导致联网失败。模型输出和长期记忆也可能出现误判，应定期检查。

机器人按已配置的聊天权限工作，建议让聊天参与者知晓它是 AI。上传自己的修改前，请检查暂存区，勿提交 `data/`、截图、日志、账号标识或本机配置。
